# hermes-setup

Provisions Nous Research's **Hermes Agent** on a fresh Debian/Ubuntu VPS: `deploy.sh` → Ansible (`ansible/`) → Docker Compose (`docker/compose.yml`) with Traefik in front. Owner is learning Hermes and configures most things (model provider etc.) in the Hermes dashboard, not in this repo.

## Layout
- `deploy.sh`: entry point. First run prompts, generates the password, writes `ansible/inventory/hosts.yml` (all settings + secrets), checks SSH (and passwordless sudo for a non-root user), then runs `site.yml`. Finally writes `credentials.txt`. Both outputs are gitignored, mode 600. Re-runs reuse `hosts.yml`.
- `ansible/`: `site.yml` (roles base → security → `geerlingguy.docker` → hermes), run as `ansible_user` with `become`. Galaxy roles/collections are pinned in `requirements.yml` and installed by `deploy.sh` or `make deps` into gitignored `galaxy_roles/` and `collections/`. Defaults are in `group_vars/all/main.yml`; inventory host vars override them.
- `docker/compose.yml`: prod. Ansible copies it verbatim to `/opt/hermes`. Keep it the single source.
- `docker/compose.dev.yml`: dev overrides layered on `compose.yml` (plain HTTP, localhost ports, `.dev-data`), with dev variables in `docker/dev.env`. Not named `compose.override.yml` on purpose: that's auto-loaded and would leak dev settings onto a server. Uses `!override` (Compose >= 2.24) to replace lists rather than merge.

## Decisions (don't undo without asking)
- **Traefik, not nginx.** The why is in `docs/reverse-proxy.md`.
- **Hermes publishes no ports, in prod or dev.** The only way in is Traefik.
- **No Traefik basic auth.** Hermes' own login is the only gate, because the Hermes Desktop app can't pass a proxy auth prompt. A friend uses it too. Planned upgrade: Keycloak via `HERMES_DASHBOARD_OIDC_*`.
- **No admin user and no bootstrap playbook.** The owner's call: the box only runs Hermes. Ansible logs in as `ansible_user`: root by default, or any user with passwordless sudo. An optional key goes in `ansible_ssh_private_key_file`, which deploy.sh pairs with `IdentitiesOnly=yes`. SSH is key-only, with `AllowUsers {{ ansible_user }}`. `PermitRootLogin` is `prohibit-password` when that user is root, otherwise `no`. UFW allows 22/80/443. fail2ban sshd: 10 failures in 10m → 20m ban.
- **No Ansible Vault.** Secrets are generated by `deploy.sh` into the gitignored `hosts.yml`.
- **Model provider is not managed by the repo.** It lives in `/opt/data/.env`, set via the dashboard.

## Verified Hermes facts (image `nousresearch/hermes-agent:stable`)
- **Image:** about 1.1 GB compressed, about 3 GB on disk. Tags look like `v0.23.4`; `-desktop` variants are bigger. No slim variant exists.
- **Process layout:** `gateway run` + `HERMES_DASHBOARD=1` runs the gateway and dashboard (port 9119) under s6. Runtime user is `hermes`, UID/GID 10000. State lives in `/opt/data`.
- **First-boot ownership bug:** on first boot `config.yaml` is seeded root-owned. It's fixed on the next restart, and the hermes role does that restart.
- **CLI:** `docker compose exec hermes hermes <cmd>` is safe; a shim drops to the hermes user. Config is managed with `hermes config get|set <key> <value>`.
- **Auth:**
  - The dashboard refuses a 0.0.0.0 bind without an auth provider; we use `HERMES_DASHBOARD_BASIC_AUTH_*`.
  - Login is `POST /auth/password-login` with body `{"provider":"basic","username":..,"password":..}`.
- **Rate limit:** 10 failed logins per 60 s **per client IP**, held in memory.
  - `dashboard.trusted_proxies` must list Traefik's IP, or all users share one bucket and a bot locks everyone out. Verified with an A/B test.
  - The hermes role sets it via `hermes config set`.
- **Traefik's IP is `.254`** (prod `172.30.0.254`, dev `172.31.0.254`). It was `.2` before, but Hermes sometimes grabbed `.2` first and Traefik failed to start.
- **Hermes Desktop** connects to `https://<domain>` (dashboard port) with the same login.

## Validate changes
`make lint`: bash -n, playbook syntax checks, and `config -q` for both prod (with `.env.example`) and the merged dev config.

## Environment gotchas
- **Branching:** default branch is `master`; commit on a feature branch.
- **zsh:** never store a command in a variable (`C="docker compose -f x"; $C ps` fails silently). Use a function.
- **macOS tools:** BSD `sed` has no `\b` (use `perl -pi`). `deploy.sh` must stay bash 3.2-compatible.
- **rtk:** a hook rewrites shell commands and can hide output (e.g. `ls`). Use `rtk proxy <cmd>` for raw output.
- **Docker:** Docker Desktop may not be running (`open -a Docker`). Big image pulls can stall on the last layer; kill and re-pull, since finished layers are cached.

## Production server
- SSH alias `hermesal` (root, key from `~/.ssh/config`); dashboard `https://hrmsal.ls.fyi`. Linode, Ubuntu 26.04 "resolute", 1 CPU / 1.9 GB RAM, swap 2.5 GB (provider's 512 MB partition + 2 GB `/swapfile`).
- Re-deploy: `make hermes` (stack only) or `make deploy`. `./deploy.sh --tags <role>` runs one role.
- Login is in `credentials.txt`; settings in `ansible/inventory/hosts.yml` (`ansible_host: hermesal`).

## Status / next steps
- **Deployed 2026-11-25** with real Let's Encrypt certs. Verified: HTTPS + HTTP→HTTPS redirect, dashboard login, `trusted_proxies`, data dir owned by 10000:10000, password SSH refused, UFW, fail2ban values; the playbook is idempotent (re-run reports `changed=0`).
- **Still to verify:** Hermes Desktop remote mode against `https://hrmsal.ls.fyi` (upstream bug reports exist).
- **Watch RAM:** Hermes idles around 470 MB. If swap use stays high or browser tools are slow, resize to 4 GB / 2 CPUs.
- **Known noise:** the image logs `install out of sync (pnpm…)`. It's harmless and comes from upstream.
- **On 1 CPU, Hermes needs about a minute to boot.** The playbook's final HTTPS check may report 502 even though the deploy worked; re-check with curl.
- **fail2ban must stay in `mode = aggressive`.** Passwords are off, so bots only leave `Connection closed by authenticating user ... [preauth]` lines, and normal mode counts none of them (verified: normal 0 matches, aggressive 13 in an hour). To check it works: `fail2ban-client status sshd` and `grep Found /var/log/fail2ban.log`.
- **Use `community.docker.docker_compose_v2_exec`, not `command: docker compose exec`.** Set `tty: false`, and add `check_mode: false` on read-only tasks so `--check` still works.
- **ansible-core is strict about conditionals:** `assert`/`when` must evaluate to real booleans. Use `is search(...)`, not `regex_search`.
